# 批量视频剪辑

## 输入
- 参考视频文件（可多条）
- 素材库目录（原始文件只读）
- 脚本/配音文案，可选
- 输出比例与目标时长

## 产物
每条任务保存于 `work/YYYY-MM-DD/<任务ID>/`：`recipe.json`、`matches.json`、`script.txt`、`voice/`、`final_voice.mp3`、`captions.srt`、`preview.mp4`、`jianying_draft/` 和 `acceptance.json`。验收通过的结果复制到 `final/`。

## 执行
1. 检查 Python、FFmpeg/FFprobe、剪映和可用 TTS；缺项先报告，再执行不依赖该项的阶段。
2. 每项任务建独立日期目录，不改写原始素材；清楚记录文件来源。
3. 用 FFprobe 读取视频信息，抽取镜头切换点和关键帧；生成带起止时间、时长、关键帧路径的 `recipe.json`，请用户确认切分。
4. 依据场景、动作、景别匹配素材；在 `matches.json` 写来源路径和置信度。低于 0.6 标记缺素材，不要硬凑。避免连续三镜头使用同一来源。
5. 校对语音文案后分段生成配音，读取真实时长。画面至少覆盖完整语音；记录参考时长与配音时长差。生成 SRT 并核对时间码。
6. 生成预览视频和剪映可编辑草稿；草稿中的媒体路径必须存在，草稿 ID、内容 ID、素材 ID 必须唯一。
7. 验收可打开、顺序正确、字幕无错不遮主体、音画同步、媒体引用存在。将结果与问题写入 `acceptance.json`。仅通过项进入 `final/`。

## 异常处理
- 无 FFmpeg：提供安装说明，保留任务输入和计划，不生成虚假的完成状态。
- 无 TTS：输出配音文本和逐段时间占位，等待用户录音或配置 TTS。
- 缺镜头素材：明确列出镜头、需要的画面和匹配置信度，等待补素材。
- 剪映版本的草稿 schema 不确定：保留标准时间线 JSON、SRT 和预览，提示用户在剪映打开前验证；不要声称草稿已通过剪映验证。
